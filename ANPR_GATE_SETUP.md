# Real-Time Number-Plate Gate Setup

This project uses the laptop camera for a real entry/exit workflow. EasyOCR
can read the Indian registration number directly when only the plate is visible
at the gate. YOLOv11 still supplies optional vehicle context when a complete
vehicle is visible. PostgreSQL matches the plate to a live reservation, and the
admin web application displays the simulated gate.

## What is real data

- Slot numbers and statuses come from PostgreSQL.
- Booking writes the selected slot and vehicle number to `reservations`.
- Entry/exit scans are saved in `gate_events`.
- Entry, exit, payment, timer and vacancy states share the reservation ID.
- WebSocket events refresh availability for other connected users.

No random plate, slot or gate event is generated by the gate feature.

## 1. Start PostgreSQL and Redis

From the `backend` directory:

```powershell
docker compose up -d
```

The database migration runs automatically when FastAPI starts. It safely adds
the reservation payment/booking fields to an existing database, creates
`gate_events`, and prepares admin-only walk-in slots `W01` and `W02`.

## 2. Install the updated backend packages

Activate the same Python environment in which the existing YOLO feature works:

```powershell
pip install -r requirements.txt
```

EasyOCR downloads its English recognition model the first time the camera is
started. Keep the internet connected for that first run. The configured
`yolo11n.pt` model is also loaded lazily.

## 3. Start FastAPI on the laptop

Run FastAPI directly on the laptop so OpenCV can access camera index `0`:

```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Close Zoom, Camera, Teams and any other program using the webcam. PostgreSQL
and Redis can stay in Docker; FastAPI should run on Windows for this setup.

## 4. Start the admin web application

From `admin_app`:

```powershell
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
```

Sign in as an administrator and open **Gate Camera**.

1. Select the parking area.
2. Choose **Entry Mode**.
3. Select **Start Laptop Camera**.
4. Hold or position only the number plate inside the yellow guide box. A full
   vehicle does not have to be visible.

For a classroom demonstration, show a sharp, front-facing plate image to the
laptop camera and fill most of the yellow guide box. The direct OCR fallback
runs even when YOLO reports zero complete vehicles.

A clear high-confidence OCR result can proceed immediately; a lower-confidence
result requires two matching observations. The gate opens when the plate
matches a live `PAYMENT_PENDING` or `PENDING` reservation inside its 30-minute
entry window. Advance payment is not required for entry.

The OCR crop is enhanced using denoising, contrast correction, sharpening and
adaptive thresholding. Exact matching is always attempted first. If OCR misses
exactly one middle character, the backend may use the registered number only
when the state code and final four digits match and exactly one live
reservation is a safe match. The admin screen shows both the raw OCR reading
and matched booking number, so a correction is never hidden.

The live preview and AI recognition run independently. The browser receives a
smooth lightweight preview while guide-box OCR runs in the background. A
comprehensive YOLO/full-frame scan still runs periodically, so complete-vehicle
detection remains available without blocking every camera frame.

## 5. User booking

The user's **Book Slot** tab displays only current `VACANT` slot numbers.

1. Select a real available slot.
2. Enter an Indian vehicle number, such as `KA19AB1234`.
3. Optionally pay the ₹10 advance.
4. Present the same number at the entry camera within 30 minutes, whether the
   advance was paid or not.

After a valid entry scan:

- gate state becomes `OPEN` for four seconds;
- reservation becomes `ACTIVE`;
- the selected slot becomes `OCCUPIED`;
- `actual_check_in` is recorded and the timer starts;
- the user can navigate to the booked slot.

## 6. Walk-in entry with W01 or W02

`W01` and `W02` are stored in PostgreSQL as `WALK_IN` slots. They are hidden
from the user booking screen and cannot be reserved through the user API.

1. In **Entry Mode**, scan the number plate.
2. When no prebooking matches, select vacant `W01` or `W02` in the admin gate
   screen.
3. Select **Admit Walk-in and Open Gate**.

The backend creates an `ACTIVE` walk-in reservation, starts its timer, marks
the selected W slot `OCCUPIED`, records the gate event, and opens the simulated
gate for four seconds.

## 7. Exit and final payment

Switch the admin page to **Exit Mode** and scan the same registration number.

- The parking timer stops.
- The final fee is ₹20 for the first hour plus ₹5 for each started extra hour.
- A verified ₹10 advance is deducted; an unpaid advance has no deduction.
- The gate displays `PAYMENT REQUIRED`.
- The slot stays occupied until Razorpay verifies the final payment.

After verification, the exit gate opens, the reservation becomes `COMPLETED`,
and the slot is broadcast as `VACANT` to connected apps.

For a walk-in, the admin selects **Record Cash** or **Record UPI** after the
exit scan. The payment record is committed before the gate opens and W01/W02
becomes vacant.

## Camera accuracy checklist

- Use a well-lit, front-facing plate.
- Put the number plate inside the yellow guide; the complete car is optional.
- Move the plate close enough that every character is sharp and readable.
- Avoid strong glare and motion blur.
- Use the same registration number entered during booking.
- A denied scan is recorded with its OCR confidence and reason.

If an older or slower laptop still needs tuning, add these optional values to
`backend/.env` and restart the backend:

```env
GATE_PREVIEW_FPS=8
GATE_YOLO_EVERY_N_SCANS=4
GATE_DETECTION_INTERVAL_SECONDS=0.35
GATE_FAST_CONFIRM_CONFIDENCE=0.70
GATE_PLATE_CONFIRMATIONS=2
GATE_DUPLICATE_COOLDOWN_SECONDS=15
GATE_OPEN_SECONDS=4
```

Do not set `GATE_YOLO_EVERY_N_SCANS` below `1`. A larger value uses less CPU;
`4` keeps YOLO active while favoring faster plate-only OCR scans.
The first three scans use the fast plate guide, and every fourth scan performs
the comprehensive YOLO/full-frame fallback. A valid OCR result at or above
`0.70` confidence proceeds immediately; lower-confidence results still require
two identical observations. Payment and reservation validation are unchanged.

## Main API endpoints

- `GET /api/v1/gate/status`
- `POST /api/v1/gate/camera/start`
- `POST /api/v1/gate/camera/stop`
- `PUT /api/v1/gate/mode`
- `GET /api/v1/gate/walk-in-slots?parking_area_id={area_uuid}`
- `POST /api/v1/gate/walk-ins/admit`
- `POST /api/v1/gate/walk-ins/{reservation_uuid}/payment`
- `GET /api/v1/gate/camera/snapshot`
- `GET /api/v1/gate/events`

All gate endpoints require an authenticated admin, manager, operator or
security account. Expired access tokens are refreshed automatically once. If
the seven-day refresh token is no longer valid, polling stops because the admin
is redirected to the login screen instead of repeatedly sending 401 requests.
